# AI 工作助手：部署位置、资源及预算

日期：2026-11-13。状态：资源调查与部署决策稿，**六项基础设施尚未部署**。用户要求六项全部可用，但先核算资源和费用，再确定部署位置；本稿不代表购买授权。

本方案覆盖 LangChain、LangGraph、RAG、Milvus、MCP、Langfuse。业务数据库继续使用 MySQL；此前 MongoDB 迁移方案不在当前实施范围内。现有业务表、打印与财务规则保持权威。

Milvus Standalone 官方列出内存最低 8GB、建议 16GB，CPU 推荐至少 4 核；Langfuse 官方 Docker Compose 方案建议至少 4 核 16GiB，磁盘示例为 100GiB。因此不能在现有 2GB 主机上把两个系统直接拉起来后当作生产可用。

依据：[Milvus 硬件要求](https://milvus.io/docs/prerequisite-docker.md)、[Langfuse 部署建议](https://langfuse.com/self-hosting/deployment/docker-compose)。

## 2. 六项分别做什么

| 项目 | 本项目职责 | 运行位置 |
| --- | --- | --- |
| LangChain | 模型、工具、检索适配器，统一超时及结构化结果 | TypeScript AI 服务内的依赖 |
| LangGraph | 意图判别 → 检索 → 解析 → 规则校验 → 草稿，限制循环/重试 | 同一个 AI 服务内 |
| RAG | 按权限检索已有资料并给出可追溯依据 | AI 服务、索引 worker、向量模型组成的流程 |
| Milvus | 保存分模块的检索投影与向量索引 | 独立容器，不替代 MySQL |
| MCP | 提供受控查询和草稿工具；真实协议发现及调用 | AI 服务的受保护内网入口 |
| Langfuse | 请求链路、延迟、token、错误和人工反馈观测 | Web/worker + 配套基础设施 |

Langfuse 自建还需要 PostgreSQL、ClickHouse、Redis 和对象存储；按用户既有要求，对象存储使用本机磁盘上的兼容服务，不创建阿里云 OSS 桶。业务库仍是 MySQL，Langfuse 的数据库仅保存其内部资料。

依据：[LangGraph](https://docs.langchain.com/oss/javascript/langgraph/overview)、[MCP](https://modelcontextprotocol.io/docs/learn/architecture)、[Langfuse 官方 Compose](https://github.com/langfuse/langfuse/blob/main/docker-compose.yml)。最终实施固定兼容版本及镜像 digest，不直接跟随 main/latest。

### 3.1 资源拆账

以下是本项目初步预留量，不是已压测的实际占用，也不是容器硬上限：

| 服务组 | 内存规划 |
| --- | --- |
| Milvus 及依赖 | 8～16GiB |
| Langfuse 及 PostgreSQL/ClickHouse/Redis/对象存储 | 12～16GiB |
| CPU embedding | 2～4GiB |
| TypeScript AI 服务、MCP、索引 worker | 1～2GiB |
| OS、缓存、部署及临时空间余量 | 4～8GiB |

合计约 27～46GiB，因此 32GB 是受控低并发起步，64GB 更稳妥。给容器设限制只是控制影响范围，不能让不够用的内存变成够用。试运行从生成并发 2、embedding 并发 1、索引 batch 4 起步，记录实际峰值后调整。

磁盘 200GB 试运行可先规划：系统与镜像 30GB、向量与元数据 40GB、Langfuse 70GB、模型及临时重建 20GB、空闲 40GB。不是全量备份容量承诺；重建采用双集合时需预留额外空间。日志、traces 按 14～30 天保留目标配置并实际验证清理效果，磁盘使用到 70% 告警。

## 4. 模型与向量

本地 CPU embedding 首选评测基线为 `BAAI/bge-small-zh-v1.5`，512维、最大位置长度512，适合先验证中文短订单、原料和待办语义查询。理解/生成模型继续用现有配置 API，**本次资源预算不含本地大语言生成模型或 GPU**。

业务代码保持 TypeScript；采用经过验证的 ONNX/Transformers.js 运行方式，固定模型源、revision、转换制品 SHA256、CLS 池化及归一化规则。FP32 先做基准，再对照评测 INT8；不能假定量化无精度影响。模型文件只下载一次保存于持久磁盘，启动预热，运行期间不访问模型仓库。

profile 示例：`bge_zh_v15_fp32_cls512_tpl1`。文本按 token 分块，包含特殊 token/查询指令的总长度不能超限，不静默截断长 SOP。更换维度、模型、池化或模板时建新集合，后台重建、验收后切换别名。

100,000 条512维 float32 的原始向量约195MiB；1,000,000条约1.91GiB。此数字仅为向量数组，不含索引、文本、元数据、日志、副本、缓存和重建空间，不能据此给服务器只配2GB。

参考：[模型卡](https://huggingface.co/BAAI/bge-small-zh-v1.5)、[配置](https://huggingface.co/BAAI/bge-small-zh-v1.5/raw/main/config.json)。

## 5. 业务链路与数据边界

```text
App 全局 AI 助手
  → 现有 API：认证、角色、输入校验
  → 私网 AI 服务（LangChain + LangGraph）
      → 意图/模块识别
      → 精确查询 + RAG 召回（本地 embedding → Milvus）
      → 用 MySQL 最新记录复核候选、版本、权限和有效日期
      → 模型解析 → Zod/日期/金额/人员业务规则
      → 返回草稿或需补充问题
  → App 原有填写页：用户核对、修改、点击创建
  → 原有业务 API 写入 MySQL

各步骤 → 异步、脱敏、有限队列 → Langfuse
MCP → 复用上述受控查询/预填服务，不直接执行任意 SQL 或脚本
MySQL 事务 + outbox → 索引 worker → 生成/更新/删除 Milvus 投影
```

- 先接待办、订单/送货历史、文档的查询与预填；BOM 金蝶商品与送货历史分集合/命名空间，严禁互相当作商品字典。
- 金额统计、订单数、逾期、加班/调休余额走确定性 MySQL 查询，不用向量结果算总额。
- 每个向量保存 source_type、source_id、chunk_id、source_version、profile_id、content_hash、scope。权限过滤在服务端确定；召回后仍重新验权，不能仅相信客户端或索引里的权限。
- 首次索引前列出范围、条数及预计耗时。只发送最小必要内容到生成 API；日志脱敏姓名、电话、完整地址，不把 embedding 服务变成额外的数据外发渠道。
- 创建/更新业务的事务里写 outbox，索引失败不会回滚成功订单。worker 幂等重试；删除有 tombstone；旧任务不得覆盖新版本；定期校验漏索引。
- MCP 首期工具拟为 `search_business_records`、`get_record`、`prepare_draft`，只读/预填，不开放自动创建/删除、任意网址抓取或 Shell。
- LangGraph 设置超时、最大步骤、重试预算；不用无限 ReAct 循环。草稿确认仍在普通业务接口，重试模型不会重复下单。
- 检索结果属于资料，不能覆盖系统规则；检索不到要明确说明。引用可打开对应记录，不能伪造出处。
- Milvus/embedding 不可用时显示检索降级，保留原有手动业务和普通解析；Langfuse 阻塞不得阻塞创建/保存。失败不能显示成成功空结果。

## 6. 部署、验收与回滚

1. 用户确定地点和预算，核实最终报价与资源可售性；购买前确认具体清单。
2. 新主机准备 Docker/Compose、持久卷、私网规则、健康检查、凭据；数据库端口不暴露公网，Langfuse 管理页独立登录。
3. 固定镜像和SDK版本，启动全部依赖并验证健康；本地模型预热、重启后无需下载。
4. 实装六项功能，不能只装包或设置一个启用标记：LangGraph 有实际节点执行；MCP 能发现/调用工具；Milvus 有真实向量查询；Langfuse 能看到一次解析的完整 trace。
5. 先使用虚构资料做隔离验收，再按确认范围建业务索引。对照中文语义查询、精确单号、同名员工、离职日期、删改索引、无匹配、越权和注入等案例。
6. 使用业务原文评估时按现有数据授权范围执行；不因启用观测默认把所有历史原文上传到新外部平台。
7. 用预期并发及两倍并发压测，记录 API 保存延迟、检索 P95、模型队列、CPU/RSS、磁盘增长、OOM和swap；32GB方案不通过则升级或分离服务。
8. 灰度启用，停用开关能回到旧解析；MySQL 是数据源，向量可重建。保存旧 collection alias、profile 与镜像版本。备份需覆盖依赖数据库、对象存储、配置及密钥恢复方式，恢复演练不能省略。
