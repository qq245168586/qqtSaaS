# 月度待办与重新开始

2026-11-15，桌面版本 2.1.31。

## 行为

- 待办类型为一次性（once）、月度（monthly）。原有任务迁移为一次性。
- 列表勾选即完成，取消勾选即未完成；没有百分比。AI 预填固定未完成，可识别原文明示的每月/月度要求，用户在填写页确认类型与时间。
- 月度任务本周期完成后保持完成。按北京时间进入下一个月，开始时间设为当月1日00:00，截止日沿用月度基准（如每月5号23:59）。月底任务始终对应月底；普通日期超过当月天数则暂取月底，不使后续月份日期漂移。
- 未完成的上周期也归档为未完成，不能伪造已完成。停机跨过多月时保留上次实际周期，直接进入当前月份，不制造中间月份的完成记录。
- 月度任务开始后、未完成时即显示红点；超过截止时间另标“已逾期”。一次性任务仍只在到期未完成时提醒。
- 已完成事项显示“重新开始”：事务内保留快照，开始取服务器当前北京时间（分钟），截止=当前时间+(旧截止-旧开始)，保留标题、备注和类型，清除完成状态。原时长可以跨天或跨年，不用固定30天代替。
- 手动重开的月度任务若跨月，其当前周期持续到新的截止月份，之后再按月循环，避免刚重开的区间被月初提前截断；重设后的截止时间成为后续月度基准。
- 修改时间或类型时更新月度基准，单纯勾选/修改文字不改变基准。删除后停止循环。历史入口查看结转/重新开始前的起止时间、完成状态、完成时间和备注。

## 实现与安全

- todo_items 新增 recurrence、cycle_month、monthly_anchor_end、completed_at、import_key；todo_history 保存只读快照，(todo_id,source_version) 唯一。
- 新增迁移 TodoRecurrence1794700800000，默认保留旧事项。禁止自动 down 删除业务数据。
- 服务启动、每60秒后台检查；列表/提醒请求及编辑、重开之前再结转。服务重启可追赶，App 不必一直打开。
- 逐行事务 FOR UPDATE，版本校验避免多端勾选、月初结转、重复重开相互覆盖。失败回滚，下一轮重试，不返回假成功。
- POST /todos/:id/restart 接收 version，仅管理员可写，仅接受已完成事项；GET /todos/:id/history 分页读取；列表支持 recurrence 筛选。
- 完成状态仍使用内部0/100存储，客户端只显示勾选状态。创建/更新必须显式提交任务类型，不允许缺字段把月度任务悄悄改成一次性。

## 月度检查首次导入

使用用户提供表格 Sheet1 A1:A15，共15行；保留每日/每周原文，按用户要求统一为月度。第3、6行相近但不相同，分别保留。
截止日：第2、14行15日；第3、6、11、12、13行5日；第4、9行10日；第15行25日；其余月底。截止当天23:59，当前周期从当月1日00:00开始；过期的当前月事项保留逾期状态。

源码只提交通用 CLI src/import-monthly-todos.ts，原始Excel与提取JSON不提交Git。CLI读取经核对的JSON，来源文件SHA256+行号作为导入唯一键，整批事务导入；相同来源重跑跳过，不能覆盖已完成或已编辑的事项。
