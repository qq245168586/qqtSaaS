# 待办事项

入口：桌面 App「总览 → 待办事项」。团队共享，不属于某家公司、不混入零售/送货单及收入统计。管理角色可新增、编辑、完成和删除；员工角色可查看。

事项标题必填，开始/截止时间必填、精确到分钟，使用北京时间，截止不可早于开始。备注可选，进度为 0–100 的整数。100 表示完成，可编辑恢复为未完成。

截止时间到且进度小于 100，事项、总览入口及待办菜单显示红点；待办菜单显示逾期数量。按服务器时间判断，30 秒轮询并在窗口聚焦时刷新，保存/完成/删除后立即刷新。未完成默认按截止时间排列；可选全部、已完成、已逾期，并搜索标题/备注。请求失败显示错误，不伪装为零条。

接口：GET /api/todos（page/page_size/status/keyword）、GET /api/todos/reminders、POST /api/todos、PUT /api/todos/:id、DELETE /api/todos/:id。修改及删除携带 version，防止覆盖他人修改；删除为软删除。MySQL 独立表 todo_items，迁移 Todos1794528000000。通过现有 JWT 验证及 Electron 路径白名单。

验证：服务端 99 项测试、桌面 96 项测试通过，两端构建通过。tests/todo-smoke.ts 使用隔离数据验证创建、编辑进度、逾期红点、完成消点、状态筛选及删除。

## 客户端兼容与错误分类（2026-11-13）

实际问题：运行中的旧页面仅接受 retail/delivery/schedule，服务端返回 todo 后被客户端校验拒绝并显示原始 Zod 错误。新客户端发送 supported_modules，服务端根据能力返回草稿；旧客户端未声明能力时按原三个模块处理。只有不支持的草稿时返回 AI_CLIENT_UNSUPPORTED，混合结果保留支持的部分并提示其余未创建。本地刷新页面后已验证待办预填成功；尚未发布新桌面安装包。

错误响应保留 code/message/data，并增加 error_code、error_stage、error_id。App 显示中文分类、操作建议与排查编号；兼容拦截旧的 JSON 校验报错。识别失败保留原文、不创建记录。日志使用同一编号，只记阶段和字段路径，不记录订单原文、模型回复、API 密钥或上游错误正文。

| 错误码 | 含义 |
| --- | --- |
| AI_INPUT_INVALID | 输入为空、过长或模块选项无效 |
| AI_CONFIG_INVALID | 模型配置无效 |
| AI_TIMEOUT | 模型调用超时 |
| AI_NETWORK | 模型服务连接失败 |
| AI_PROVIDER_AUTH | 模型服务认证失败 |
| AI_RATE_LIMIT | 模型请求限流或额度不足 |
| AI_PROVIDER_UNAVAILABLE | 模型服务不可用 |
| AI_OUTPUT_JSON | 模型未返回有效 JSON |
| AI_OUTPUT_FIELDS | 模型返回字段不符合规则；提示具体条目与字段 |
| AI_SCOPE_MISMATCH | 结果不属于当前所选模块 |
| AI_CLIENT_UNSUPPORTED | 当前客户端不支持识别出的模块 |
