# 成本核算第一期：需求与技术设计

## 1. 范围

成本核算是独立一级模块，不与送货单自由商品库互通，也不把金蝶 BOM 商品直接当作成本价格。第一期包含原材料成本库、价格版本、AI/文件导入预览、成本 SOP、确定性单位换算、成本计算快照和材料语义候选。

AI 只生成草稿。所有材料及 SOP 都必须由操作人员在同一张校对表确认后保存；模型不能直接写正式集合。

第一期不计算人工、水电、房租、管理费用和库存移动平均成本，也不自动修改金蝶资料。

## 2. 数据边界

考虑到当前服务器资源有限，第一期成本域与现有业务共用MySQL 8，通过独立表和事务隔离，不部署MongoDB、mongot或embedding服务。

数据表：

- `cost_materials`：原材料主档和别名。
- `cost_price_versions`：不可覆盖的价格版本。
- `cost_sops`：已确认成本 SOP 及当次价格快照。
- `cost_calculation_snapshots`：独立核算留底。
- `cost_import_jobs`：确认导入记录。

材料可以是两家公司通用、趣趣特专用或天美意专用。同名、同品牌、同规格、同范围导入时更新同一主档并追加价格版本，不建立重复主档。通用 SOP 只能使用通用原料；公司 SOP 可以使用通用原料和本公司原料。

## 3. 金额和单位

数据库金额使用 BSON `Decimal128`，服务端计算使用 `decimal.js`。不使用 JavaScript `Number` 计算金额。

- 采购价格和净含量原样保存。
- 基础单位成本保留 8 位小数。
- 行成本、本批成本和单个成本保留 8 位小数。
- 只有生成对外财务金额时才按对应业务规则舍入到分。

第一期只自动换算明确的同维度单位：毫克/克/千克/斤、毫升/升以及相同计数单位。没有密度时不把克和毫升互换，也不猜测一盒等于多少克。

## 4. 导入链路

```text
XLSX / CSV / TXT / 粘贴文字
  → 脚本提取工作表和单元格
  → 服务器配置的理解模型规范化
  → Zod 严格验证固定 JSON
  → 整批预览及修改
  → 用户确认
  → 写入材料主档并追加价格版本
```

缺少名称、净含量、价格、单位或生效日期的行不会被模型编造。用户需要在预览表补齐后再提交。

## 5. SOP 链路

SOP 粘贴后，模型只提取成品、产量及材料行。候选按标准名称和已确认别名精确匹配；无法匹配时集中在同一表格人工选择。价格及单位是否合法始终由代码校验。

保存时按核算日期读取每种材料不晚于该日期的最新价格版本。SOP 保存材料名称、数量、基础单位、价格版本、单位成本和行成本快照，因此以后价格变化不会改写历史成本。

## 6. 模型

理解模型继续通过服务器现有AI运行配置调用。客户端不接触模型地址或密钥。第一期不部署embedding和向量索引；后续服务器扩容后可在不改变成本主数据的前提下增加候选召回层。

## 7. 配置

成本表通过 `Costing1792600000000` 迁移创建。部署前先备份MySQL，运行 `npm run db:migrate` 后再启动新版API。

## 8. 验收

- 18.50 元、125 克得到 `0.14800000元/克`。
- 1 元、3000 克得到 `0.00033333元/克`，不会舍入为零。
- 价格更新追加版本，旧 SOP 成本不变。
- AI 导入未确认时数据库没有正式记录。
- 无法匹配的 SOP 原料集中在同一表格选择。
- 通用/趣趣特/天美意范围不串用。
- AI服务不可用时仍可手工建立并保存SOP。
- BOM 金蝶商品和送货自由商品不会进入成本集合。
