# 员工管理与排班需求文档

版本：2026-10-12 更新，解除历史排班编辑限制。本文以本轮用户指令为准，员工和部门不区分公司。

## 1. 目标与范围

桌面 App 新增一级「员工管理」，二级为「员工资料」「排班管理」。保留既有部门、员工 ID、历史任务及署名；不复制人员、不新建公司的员工副本。网页不增加排班导航，但其任务选人和保存必须遵守同一离职日期规则。

本期实现人员维护、按天排班、离职日期、分钟级加班/调休登记、跨月累计和修改审计。服务器部署到现有阿里云生产实例，桌面本地运行验收，不发布安装包。不实现工资计算、打卡、法定节假日推断、请假审批、累计余额手工调整或期初余额导入。

## 2. 人员资料与离职

员工包含姓名、全局部门、电话、在职状态、离职日期。沿用员工表的现有五位员工；新增员工需姓名与有效部门。编辑姓名或电话不改变旧单据的姓名快照；部门变动仍受现有未取消任务保护。

列表显示姓名、部门、电话、状态、离职日期，支持新增、编辑、离职。员工入口使用离职代替删除，保留历史记录和排班余额。离职操作一次填写日期并确认；日期可补录过去日期或预约未来日期。日期按中国标准时间解释，离职当天起不可用于新分配。当员工已有离职日期时不允许改回在职或重写日期，以免静默改变历史资格；返聘/纠错需后续独立履历功能。

历史单据按业务日期判定人员资格：任务用预计交付日期，缺失时已有任务用原创建日期，新任务用服务器当天；送货单用送货日期。离职日期为10月1日时，9月30日及以前可选，10月1日及以后不可选。允许修改离职前单据，禁止借由历史记录例外给离职后业务重新分配该员工。员工候选和服务器最终校验同时遵守此规则。

送货单署名仍是可自定义文本，不强制关联员工、不与 BOM 商品库互通；当署名明确对应员工姓名时，也按送货日期检查资格。历史自由输入的非员工署名继续可用，不要求变成员工。重名时只要有同名有效员工即可，不猜测身份。

离职后的已有排班仍可查看、清除，不可新增或修改为工作/加班。历史排班保留，余额不清零。预约离职的员工到离职前仍可以排班。

## 3. 每日排班

每日每员工至多一条有效排班。以员工ID和工作日唯一定位，输入班次类型、开始时间、加班分钟、调休分钟、备注。支持任意分钟开始，包括跨午夜；归属开始日。

- 工作：默认08:00开始，标准结束为开始+9小时，包含1小时休息，有效工作8小时。09:00对应18:00。标准结束时间自动计算，不另设自由结束字段。
- 休息：没有标准工作时长；可以登记额外加班。
- 调休：默认调休480分钟（8小时），允许部分调休。工作类型也允许填写部分调休。
- 加班、调休可按小时输入，最小1分钟。存储和计算全部使用整数分钟；UI显示换算小时与分钟，不用浮点累积。一天加班最多960分钟，调休最多480分钟，调休日不能同时登记加班，减少含义冲突。可用「工作」记录同日部分调休及额外加班。
- 工作+加班的休息/加班具体起止区间本期不记录，标准结束时间仅指正常班，不声称是打卡或最终离岗时间。
- 没有排班的日期是「未排班」，不自动认定缺勤、不自动减8小时。周末不自动休息。

日历按月展示所有现有员工，每日单元格显示班次、开始/标准结束、加班或调休。可切换月份、部门筛选；有余额的离职员工也保留在月汇总中。每日编辑窗含预计工作量说明。过去、今天和未来日期均可新增、修改或清除排班。日期仍须为2000至2099年的真实日期，离职资格和版本校验保留。历史补录、修改、清除后，小时余额和累计起始月以来的例休余额按明细重新计算。

## 4. 累计口径

日净值 = 加班分钟 − 调休分钟。累计余额 = 系统已登记、工作日小于等于服务器当天的所有日净值之和。正数代表可继续调休，负数代表调休超过加班，下一月继续累计；负数只提示余额不足，不禁止调休、不自动扣工资。

月期初 = 月初之前已发生的累计。月内发生 = 当月截至当天的加班、调休。月末/截至余额 = 期初 + 月内净值。未来月份显示其截至今天余额，未来计划单独展示预计净值，尚未发生不计入余额。本月和历史月份完整保留，下一月无需「结转」按钮或结账程序。清除任意日期的排班从统计中扣除相应净值，不删除审计记录。

例如9月累计+180分钟，10月调休300分钟，余额−120分钟；11月登记加班480分钟后余额+360分钟。未排班不产生负值。新员工初始余额0；本期不虚构已有员工过往加班。

同一天同时编辑时使用版本号防覆盖：后保存者收到冲突提示，刷新后重新确认。禁止修改累计值的表单、API与管理菜单。

## 5. 数据与访问

员工、部门、排班全局共享；单据公司仍仅用于单据归属。公开桌面工作台沿用既有授权模式；私有账号模式只允许 boss/admin 写排班，普通 employee 不开放此模块。所有写入必须经服务器，离线缓存只读，失败不能假成功。

排班保存/清除和离职使用数据库事务。保存审计包含员工、日期、前后值、操作人、服务器时间；禁止覆盖历史审计。用户单据、员工和附件不被清空。部署前做全量备份。排班不包含在旧版「公司备份」恢复范围；既有公司恢复接口不写全局员工或部门，运维用全库备份保护全局排班。

## 6. 验收

1. 现有员工无公司字段、不重复；新增后日历可排班。
2. 08:00→17:00，09:00→18:00，23:30→次日08:30；均含1小时休息。
3. 过去、今天、未来均可新增、修改、清除；无效日期仍拒绝；历史更改重算跨月余额与例休天数。
4. 分钟准确累计，正负跨月保留；未来不提前入账，空白日期不扣时长。
5. 两人并发不互相覆盖，清除后重建不允许旧版本请求覆盖。
6. 离职前单据可选人，离职日及后不可选；服务器绕过UI提交也拒绝；署名习惯不带出离职后不合资格员工。
7. 有排班员工不会通过目录删除丢失历史；过往单据、模板、商品库均保留。
8. App模块可切换，离线明确报错；服务器迁移、构建和测试通过；本地run，无安装包发布。
