# 例休与未休天数

2026-10-06。按用户关于“本月应休四天、休一天剩三天、月底未休跨月累计”的例子，采用每月四天例休。此天数余额与原有加班减调休的小时余额独立，不自动折算小时或工资。

## 计算规则

- 现有员工自本功能上线当月（2026-10）开始累计，初始旧结余为零，不虚构此前月份未记录的休假。
- 每月额度四天，新员工从创建当月开始，首月暂不按入职日折算；离职月份有在职日期则保留该月额度，离职当月起完全不在职及之后月份不再发放。
- 排班中的 `rest` 为一天例休。`work`、`comp_leave`、未排班、软删除和登记过加班的休息日不算完整已休天数；调休仍只扣小时余额。
- 实际发生的例休到服务器上海日期当天计入，未来例休单独显示计划；未来月份的四天不提前计入实际余额。
- 本月未休 = max(本月四天 − 本月已休, 0)。先消耗本月四天，超出四天的例休再消耗旧结余。
- 结余未休 = max(月初结余 − max(本月已休 − 本月额度, 0), 0)；未休合计 = 本月未休 + 结余未休。月末剩余即下月月初结余。
- 若实际例休超过全部可用天数，单独显示额外休息天数，未休不会显示负数，不自动扣工资或形成下一月欠休。
- 从明细与起始月计算每月额度和余额，不写可手工调整的余额、不需要月末定时任务，刷新和重复查询不会重复结转。

例如10月休三天，月底余一天；11月初有旧结余一天和本月四天，共五天。11月休满四天后仍余一天，休第五天才消耗这一天旧结余。

## 实现

- 服务器 `employees.rest_start_month` 保存只读累计起始月；迁移为存量员工初始化上线月份，再次执行不覆盖；新员工由资料创建接口设置，不允许客户端提供或修改。
- `employee-rest.ts` 纯函数根据员工、排班和服务器日期按月计算；员工ID和排班唯一日期保证同一例休日不会重复扣减。
- 既有 `GET /employee-schedules` 增加 `rest_monthly_quota_days` 和独立 `rest_balances`，原 `balances` 小时字段及保存合同不变，旧App仍可使用。
- 桌面在排班页单独显示例休天数表；班次明确区分例休和调休。小时表增加按计划执行后余额，避免把未来净值误解为最终余额。
- 新桌面兼容缺少新字段的缓存/旧服务器，明确要求刷新，不伪造零余额。

2026-10-12 起历史、当天和未来排班均可改；修改明细后自动重算未休天数，不转换调休数据、不提供累计余额手工编辑。
