# 第二期实施约定与规格差异

日期：2026-09-22。原始输入保存在 `docs/reference/`，不修改原文。

## 已明确采用

- 新目录独立工程，桌面合并送货及任务、H5仅任务、云端数据共享。
- 总仓库通过三个 Git submodule 连接 server/desktop/web，替代文档单体仓库示例。
- 业务及工具代码 TypeScript strict，不在旧项目原位改造或自动覆盖旧 SQLite。
- ID 在 JSON 中用字符串表示，避免 MySQL BIGINT 超出 JS 安全整数。
- 输入 schema 严格检查，拒绝客户端 company_id；公开模式允许 company_code 指定单据归属、跨公司选择目录关联。
- 用户最新要求公开共享工作台，覆盖初始员工隔离及登录要求：自动进入，不先选公司，两公司业务数据共享。普通员工/公司隔离规则仅用于保留的非公开模式。
- 公开会话不签发刷新凭据，不允许管理账号/改密/备份；非公开模式仍保留随机初始密码、首次改密、web安全Cookie及desktop safeStorage。访问令牌不放localStorage。
- 任务转单以公司+来源任务防重，草稿单号为空，正式保存才分配单号；单号分配串行化，金额 decimal.js。
- 原系统公司数据按原标记迁移；没有公司标记的旧任务必须先明确目标公司。

## 环境差异

实例 `i-bp1gy4to0n4dh5gk7tuw` 是阿里云 Linux 4，约 1.6 GiB 内存，不是文档示例 Ubuntu。因此采用系统发行的 Node.js 22 / MySQL 8.0 / Nginx 和 systemd；不直接执行文档中的 apt 命令，也不额外叠加 PM2 守护进程。

MySQL 和 Git HTTP 后端只监听 loopback。Nginx 提供 TLS 入口。按用户要求直接用 IP，已启用公开可信的 Let’s Encrypt IP 证书，每 6 小时自动检查续期；客户端无需导入临时自签证书，不关闭 TLS 验证。NestJS 升级到 11.2.5，以修复原 10.x 依赖审计发现的问题。

## 对原文矛盾的处理

原文对哪些表软删除有多处不同概括，以具体表结构与业务规则为准；图片、明细不能假定自动级联，因为设计没有物理外键，服务层必须处理。原文称外键会阻止软删除并不准确，使用逻辑外键是本期设计选择，不以该说法作为安全保证。

原文部分示例按字符串日期格式化筛选，与索引优化章节不一致；实际按月起止范围并对预计日期为空回退创建日期。

原历史送货单号与新三位序号格式不同，迁移保留历史单号，不重编、不把旧单标成坏数据。

## 用户后续确认（覆盖原文）

- RxJS + reducer（scan）已确认，不需要rxjs-reduce包。
- 只用公网IP，不购买域名；已申请Let’s Encrypt IP证书并配置每6小时检查续期。参考[官方IP证书说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)。
- 原任务库全部归入天美意tmy。
- 不使用OSS，仅服务器本地私有磁盘；未创建OSS桶、RAM角色或绑定任何IAM权限。源码改用签名文件API。
- 已明确授权新管理员账号对指定H5地址做只读联调，验证已通过。
- 用户明确知情选择“公网也免密”，随后要求取消进入前公司选择及公司数据隔离；公司仅保留为单据归属。公开模式通过PUBLIC_ACCESS开关启用，不影响Git账号密码要求。已编号单据主动更换公司时，按目标公司重分配编号并更新子项归属；历史单据未被主动修改时保持原编号。
- 用户最终将网页改为固定密码入口、无需账号；App仍免密。WEB_ACCESS_PASSWORD保存在服务器受限环境文件，网页登录密码不会存储到浏览器，2小时会话过期重新输入。该密码是网页入口校验；按用户要求，App的公共API入口仍免密，不将网页密码宣称为整个API的访问隔离。
- 不同公司的原始Excel版式不同：混合公司批量导出保存在一个工作簿中，按公司分工作表；同公司两张单仍合在同一原版工作表。桌面合打印按每张单据归属选择抬头和模板。
