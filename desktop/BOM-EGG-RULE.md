# BOM 整蛋折算规则

2026-10-06：仅修改 App，本轮不发布安装包、不修改线上服务或历史 BOM。

2026-10-06 后续：用户已要求发布 App 更新，该规则纳入 Windows 2.1.16；线上服务和历史 BOM 不变。

AI API 继续提取原配方。App 接收解析结果后运行 `foldRecipeEggs`，将普通鸡蛋蛋黄和蛋白按规格分组，折算为完整鸡蛋，然后重新读取独立金蝶商品目录匹配鸡蛋；不会沿用蛋黄/蛋白商品编码。其他材料保留原样，送货单流程不受影响。

- 拆蛋颗数 = 向上取整（蛋黄所需颗数与蛋白所需颗数的最大值）。配方中独立使用的整蛋另外计入；没有写出的另一部分视为损耗，不跨配方抵扣。
- 克数先按用户填写的每颗蛋黄、蛋白出成重量折算，不能按克数 1:1 比较。整蛋原料克数以蛋黄与蛋白重量之和换算。默认按整蛋50g、蛋黄17g、蛋白33g近似估算；没有设置也直接生成，不弹出重量确认。可手动修改参数或在金蝶微调。
- 默认鸡蛋输出为“个”。按 g/kg 输出时，默认按每颗50g库存计量重量换算，允许按实际库存口径修改，不用蛋黄克数直接代替鸡蛋消耗。
- 明确采购、购买、外购、袋装、盒装、成品蛋类，以及蛋液、蛋粉、鸭/鹅/鹌鹑/咸蛋不自动合并；蛋黄酥等成品名称不当作蛋黄原料。
- 设置通过现有 RxJS + reducer 保存到状态，使用 `bom-egg-profile-v1` 在本机持久化。设置修改后用于下一次解析；已生成草稿和历史 BOM 的数量不会随设置变化。
- 合并行保留原始各行；原始完整配方仍保存为 source_text。折算版本、参数快照、整蛋消耗和剩余部分写入物料备注，沿用现有金蝶导出列。
- 唯一鸡蛋商品的个/g/kg单位自动按50g（或手动设置重量）换算，避免因单位不同多弹一次确认。未匹配的整蛋商品仍通过现有批量确认弹窗处理。多个鸡蛋商品候选时不自动替用户选择；保存时阻止折算单位与用量单位不一致。

验证：Desktop 60 项单元测试、严格类型检查及本地构建通过。`node --import tsx tests/bom-eggs-smoke.ts` 使用本机模拟 API 与临时 Electron 配置验证按个合并、克数默认估算、不弹重量确认、复用解析结果、重新匹配鸡蛋以及保存单行整蛋和损耗；没有写入生产测试 BOM。
