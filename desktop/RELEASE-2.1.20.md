# Windows 2.1.20 发布记录

## 变更

- 全局 AI 工作助手支持零售订单、自由商品送货单、员工排班；顶部入口与 Ctrl/⌘+K。移除独立 AI 订单页面，草稿只预填既有表单，最终由用户确认创建。缺少交付日期不可保存；有日期无具体时间默认 09:00；工作班跨度9小时含1小时休息，整天调休8小时，例休单独计算。
- 修复生产模型返回 null 默认枚举、日期仅到日或 ISO 时间，以及未提及加班/调休分钟数 null 引起的校验失败。未知员工、日期、数量和价格保持待填写，不生成伪造ID。
- 打开填写页时卸载 AI 抽屉，避免隐藏面板影响送货表单焦点和可访问性。跨模块草稿保留、保存后防重复创建。
- 2.1.7 入口采用 React 19 不兼容的静态 Modal.confirm，且没有后来引入的兼容补丁；该缺陷位于旧客户端，不能通过修改更新清单修复。新版更新入口使用受控 Modal。
- 安装助手改为 Windows 系统目录绝对路径；确认包存在并收到就绪信号后才关闭 App，捕获异步启动失败、提前退出及超时。更新错误保留可见入口，提供重新检查和可信固定更新源的手动下载安装包。
- 关闭第二条“退出时自动安装”路径，避免与等待退出的助手重复启动安装器。NSIS 恢复规则加入已报告的 2.1.7 旧安装，业务 AppData 不被删除。

## 验证

- 桌面89项、服务端86项测试通过；strict 类型检查、Vite/Electron 构建和 NSIS 打包成功。
- 本地 App 连接生产 API，使用经用户明确允许发送到已配置 DeepSeek 的虚构样例完成真实模型回归：三种商品合并一张趣趣特订单、09:00默认、微信渠道及200元金额；天美意自由新品面条10斤×22元=220元；洪双武09:00至18:00，加班1小时；另日调休8小时；无日期生日蛋糕保持空白并提示补填。
- 三种原填写表单均打开核对，无业务记录保存；送货表单焦点修复再次验证。测试结束刷新清除本地虚构草稿。
- 安装助手失败时保留旧App、异步错误状态恢复、就绪握手、路径注入拒绝和更新受控窗口有回归覆盖。
- 安装包版本及 main/launcher/updater/renderer 与本次构建逐文件一致，SHA512和大小与清单匹配。
- 没有 Windows 实机，因此未宣称已完成2.1.7实机覆盖安装或下一轮原生自动升级；受影响用户应通过本版安装包完成一次手动覆盖升级。Mac自动更新不在范围内。
